## 2. New findings

### K4-LOW-1 (NEW) — RUNBOOK row overstates the URL-reuse case
**File:** `RUNBOOK.md:108`. The row says a live `'open'` claim "is never stolen (reuses the session URL)". Code (`billing.ts:361-379`) only hands back the open session's URL when the retry's `plan_id` AND `billing_interval` **match** the claim; on plan/interval mismatch the user still gets 409 `CHECKOUT_IN_PROGRESS` — no URL reuse. An operator following the row would tell a plan-switching user "click again and it resumes", which is wrong.
**Impact:** LOW — docs accuracy; no security/money vector.
**Fix:** change parenthetical to "(keeps the 409, or reuses the session URL when plan/interval match)".
**Duplicate check:** grepped `.audit-pass{1..10}-*.md` — the RUNBOOK 409 row is new in pass#10; no prior report mentions it. New.
