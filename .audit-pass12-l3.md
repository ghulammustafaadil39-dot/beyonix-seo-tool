## 3. NEW findings

### L3-L-1 — LOW — ErrorBanner still titles `incomplete` tenants "Plan limit reached."
**Files:** `frontend/components/ErrorBanner.tsx:126` (title render), `:89-90` (`noPlan` wiring)

**What's wrong.** The pass#11 fix (K3-L-1) changed only the banner *message* for `incomplete`. The headline is rendered separately at `:126`:

```tsx
{err.noPlan ? 'Free trial ended.' : 'Plan limit reached.'}
```

and `noPlan` is set to `trialEnded` (`:90`), which is `false` for `incomplete` (the `incomplete` branch never touches it). So an `incomplete` tenant — first payment never succeeded, no plan limits were ever hit — now sees the headline **"Plan limit reached."** above the corrected message. That is the exact phrase K3-L-1 was filed to remove for this state; the fix moved the lie from the message into the title. The CTA (`:135`) also still reads "Upgrade plan" rather than the payment-completion language the message uses.

**Trigger (reachable):** checkout → first payment fails → any write attempt while `incomplete` → 403 `READ_ONLY_MODE` → banner.

**Impact:** confusion-only; the CTA lands on `/dashboard/billing` where the correct `incomplete` explainer and portal CTA live, and the message itself is now accurate. LOW.

**Fix:** extend the cause-branching to the title/CTA, e.g. compute `const paymentIssue = incomplete || past_due` and render title `'Payment incomplete.'` / CTA `'Complete payment'` for that class, keeping `'Plan limit reached.'` / `'Upgrade plan'` for genuine quota cases.

**Duplicate check:** grepped all `.audit-pass{1..11}-*.md` for `Plan limit reached` + `noPlan` + title. Prior work (pass6-f3, pass7-g3, K3-L-1) addressed the message and the trial-expired case only; no report flagged the title line for `incomplete`. **NEW.**

### L3-L-3 — LOW — billing page's generic read-only alert contradicts its own state-specific alerts
**Files:** `frontend/app/dashboard/billing/page.tsx:393-397` vs `:399-404` (past_due), `:410-419` (incomplete)

**What's wrong.** `{sub?.read_only && (...)}` renders *"Your account is read-only. Subscribe to restore full access."* for **every** read-only tenant — including `incomplete` and grace-consumed `past_due` tenants, for whom "Subscribe" is the wrong action (they must *complete* / *fix* a payment, and subscribing again would mint a second subscription). So the page simultaneously tells a payment-failed tenant to "Subscribe" and to "Complete payment" — contradictory recovery guidance on one screen.

**Impact:** confusion-only; the correct CTA is present and dominant (the specific banners render with their own portal buttons). LOW.

**Fix:** scope the generic line to the states it describes — e.g. render it only when `sub?.read_only && !['incomplete', 'past_due'].includes(sub.status)`, or change the copy to "Manage your subscription below to restore full access."

**Duplicate check:** grepped all prior reports for `Subscribe to restore full access` — zero hits. **NEW.**
