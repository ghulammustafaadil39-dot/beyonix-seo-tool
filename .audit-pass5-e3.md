## NEW findings

### MED-1 — MEDIUM — Trial-expiry 402 (`SUBSCRIPTION_REQUIRED`) has no graceful frontend UX

- **Files:** `frontend/components/ErrorBanner.tsx:36`; `frontend/app/dashboard/billing/page.tsx:330-332`; backend `backend/src/middleware/requireSubscription.ts:55-60`.
- **What's wrong:** When the server-side 14-day trial lapses, `requireActiveSubscriptionOrTrial`
  throws **402 `SUBSCRIPTION_REQUIRED`** ("Your free trial has ended — subscribe to keep
  using paid features.") on every spend route and flips the tenant `read_only`.
  The frontend's upgrade treatment in `ErrorBanner` fires **only** for
  `e.code === 'LIMIT_EXCEEDED'` — `SUBSCRIPTION_REQUIRED` renders as a plain red
  error banner with **no "Upgrade plan" / "Subscribe" link**, no persistent global
  banner, and no trial countdown anywhere (the billing page shows a countdown only
  for Stripe `sub.status === 'trialing'`, never for the server-side
  `tenants.trial_ends_at`; `DashboardChrome` has zero trial UI). After the tenant
  goes read-only, mutations fail with 403 `READ_ONLY_MODE` → also generic errors.
- **Concrete trigger:** Let the 14-day trial expire → click "Run audit" (or any
  paid action). Result: red banner "Your free trial has ended — subscribe to keep
  using paid features." with a Dismiss button and **no path to /dashboard/billing**.
  The user must discover billing via nav/keyboard shortcut. This is the primary
  monetization gate and its dead-end UX is broken by omission.
- **Fix:** Extend the upgrade condition to `e.code === 'LIMIT_EXCEEDED' || e.code === 'SUBSCRIPTION_REQUIRED'`
  (or treat 402 + `upgrade` flag generically), so the amber banner links to
  `/dashboard/billing`; surface the server-side trial end date (needs a backend
  field — `GET /billing/subscription` currently returns only the Stripe row's
  `trial_ends_at`) as a dashboard-wide countdown/banner before expiry; add an
  explicit read-only notice when `Subscription.read_only` is true.
- **Duplicate check:** grepped all `.audit-pass{1,2,3,4}-*.md` — no prior finding
  mentions `SUBSCRIPTION_REQUIRED`, the trial-gate UX, or the missing countdown. **NEW.**

### LOW-1 — LOW — Failed invite-accept leaves the one-time token in sessionStorage

- **File:** `frontend/app/dashboard/team/accept/page.tsx:50-55`.
- **What's wrong:** `sessionStorage.removeItem('bseo_invite_token')` runs only on
  the success path. If `acceptInvitation` throws (expired invite, 403 wrong email,
  network error), the token stays in `sessionStorage` for the tab's lifetime.
  Single-use and email-bound, so practical impact is minimal — but it's a stale
  credential lingering in JS-readable storage beyond its useful life.
- **Concrete trigger:** Accept an expired invite → error shown, token still in
  `sessionStorage` (DevTools → Application → Session Storage).
- **Fix:** move `removeItem` into a `finally`/also-on-error branch (or clear
  before the API call, keeping a local copy).
- **Duplicate check:** prior L-4 covered sessionStorage *holding* the token as a
  pattern ("acceptable as-is"); the stale-on-failure retention is a distinct
  nuance. Reporting as NEW (LOW).

### LOW-2 — LOW — Untrusted backlink `source_url` rendered into `href` with no scheme check

- **File:** `frontend/components/tabs/BacklinksTab.tsx:128`
  (`<a href={b.source_url} target="_blank" rel="noreferrer">`).
- **What's wrong:** `source_url` comes from crawled third-party backlink data.
  React does not block `javascript:` URLs in `href`; a crafted `source_url`
  would execute on click. `rel="noreferrer"` mitigates `window.opener`, but not
  the scheme itself. Backend grep found no http/https scheme validation on
  `source_url` at write time either (backend-side; out of this pass's scope to fix).
- **Concrete trigger:** A backlink row whose `source_url` is `javascript:…`
  (requires attacker-influenced crawl data) → user clicks the link → script runs
  in app origin.
- **Fix:** validate `/^https?:\/\//i` before rendering the anchor; render non-matching
  values as plain text.
- **Duplicate check:** no prior audit mentioned `source_url`/href scheme. **NEW.**
