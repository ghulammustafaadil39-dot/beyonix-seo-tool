## 2. NEW findings

### K1-LOW-1 (NEW) — LOW — public `/api/v1/openapi.json` enumerates the entire admin API surface, defeating the 404-not-403 back-office obscurity control
**Files:**
- `backend/src/routes/openapi.ts:7-10` — `GET /openapi.json` with **no preHandler** (public, unauthenticated)
- `backend/src/index.ts:98-104` — root `onRoute` hook records **every** route's `{method, url, schema}`, including nested plugin contexts
- `backend/src/routes/admin.ts:77-364` — admin routes registered on the same `v1` instance (`index.ts:156`), all with JSON schemas: `GET /admin/tenants`, `POST /admin/tenants/:id/suspend|unsuspend|plan|credit`, `POST /admin/impersonate`, `PUT /admin/feature-flags/:key`, DLQ replay, etc.
- `backend/tests/c-07.test.ts:41` — `expect(spec.paths['/api/v1/admin/tenants']?.get).toBeTruthy()` **enshrines** the leak in the test suite

**What's wrong:** `requirePlatformAdmin` (`backend/src/middleware/access.ts:194-201`) deliberately returns **404-not-403** — "the back-office must not be discoverable (frozen contract §3.3 — no existence leak)". But any unauthenticated `GET /api/v1/openapi.json` returns the full admin path catalog **plus the request-body schemas** (`buildOpenApiSpec` copies `s.body` into `operation.requestBody` — `services/openapi.ts:95-101`). An attacker learns, for free: every admin endpoint path, the impersonation parameters (`impersonateSchema`), the credit schema (including the $100k `amountCents` maximum), the plan-override schema (including the `force` flag), and the suspend/unsuspend shapes. The obscurity control is completely nullified for discovery purposes.

**Impact:** LOW — reconnaissance only. The actual authorization (`requirePlatformAdmin` → 404 for non-platform-admins) is intact and was re-verified this pass, so no bypass, no data breach, no privilege escalation follows from the disclosure alone. But it hands a targeted attacker the exact map of the highest-privilege endpoints (impersonation, credit grants, plan overrides) with their parameter shapes — precisely what the 404-not-403 control was built to deny.

**Suggested fix:** exclude `/admin/*` from the recorded routes (filter in the `onRoute` hook at `index.ts:98-104` or in `buildOpenApiSpec`), or require authentication for `/openapi.json`. Update `c-07.test.ts:41` to assert the admin paths are **absent** from the public spec instead of present.

**Duplicate check:** grepped all `.audit-pass{1..10}-*.md` for openapi/admin-path discussion — the only hits note that `openapi.json` is "public by design" (pass#4-d4, pass#7-g1) without ever mentioning that admin paths are included. Fellow pass#11 auditor K4 (docs/OpenAPI scope) noted only that the spec documents 200+400 responses, not the admin disclosure. **NEW.**
