## HIGH

### E1-H-1 — Trial gate misses the on-page analyzer: expired-trial / unverified tenants can burn LLM budget, and the GET variant bypasses the read-only safety net too

**Files:** `backend/src/routes/onpage.ts:279-295` (`POST /sites/:id/onpage/analyze`), `backend/src/routes/onpage.ts:297-313` (`GET /sites/:id/onpage`); `backend/src/middleware/requireSubscription.ts` (wiring doc); `backend/src/middleware/auth.ts:268-285` (`enforceTenantState`).

**What's wrong:** Both on-page analysis endpoints call `analyzeUrl()` → `generateMetered(tenantId, { prompt, maxWords: 600, siteId })` (onpage.ts:257) — real LLM spend metered against `ai_words`. Their only preHandler is `requireRoleOrScope(['owner', 'admin', 'editor'], 'onpage:write')`. They carry **neither** `requireVerifiedEmail` **nor** `requireActiveSubscriptionOrTrial`. The gate's own wiring doc (`requireSubscription.ts`) lists exactly the 8 files to wire — `keywords, ranks, content, geo, audit, reports, competitors, backlinks` — chosen by the heuristic "all routes carrying requireVerifiedEmail for paid use". onpage's spend routes never carried `requireVerifiedEmail`, so the heuristic silently skipped the one spend surface that needed both gates most. This also violates `requireVerified.ts`'s own contract ("Unverified accounts … cannot trigger … content/geo generation" — on-page analysis *is* LLM content generation).

Worse, the read-only backstop doesn't cover it either: `enforceTenantState` (auth.ts:271) only blocks `POST/PUT/PATCH/DELETE` for read-only tenants. The **GET** variant (`GET /sites/:id/onpage?url=…`, which the code itself notes "triggers the same paid LLM work as the POST", onpage.ts:309) sails through read-only mode. And the `read_only` flip itself is lazy — it only happens inside `requireActiveSubscriptionOrTrial`, which never runs on these routes — so an expired-trial tenant that goes straight to onpage is never even flipped, and the POST variant works for them too.

**Concrete trigger:**
1. `POST /auth/signup` → verify email (or don't — no verified gate here) → let the 14-day trial lapse with no subscription.
2. `GET /api/v1/sites/:id/onpage?url=https://<own-domain>/some-page` → `200` with LLM suggestions, `ai_words` metered. No `402 SUBSCRIPTION_REQUIRED`, no `403 READ_ONLY_MODE` — repeatable up to the plan's monthly `ai_words` quota, every month, forever. The POST variant works identically until/unless some *other* gated route flips the tenant read-only.

**Fix:** add `requireVerifiedEmail, requireActiveSubscriptionOrTrial` to both onpage routes (order: verified → trial → role/scope), and add `onpage.ts` to the wiring list in `requireSubscription.ts`'s doc comment so the next wiring sweep doesn't re-miss it. Consider also whether `enforceTenantState`'s GET exemption is sound for any other GET-with-side-effects route (this was the only GET-with-spend found).

**Duplicate check:** grepped all `.audit-pass{1,2,3,4}-*.md` and `.audit-pass5-e3.md` — prior onpage mentions are S-09 prompt-injection (pass2-b1) and `sanitizeJsonLdForScript` (pass4-d1); no prior finding mentions the trial gate, `SUBSCRIPTION_REQUIRED`, or verified-email on onpage. **NEW.**

## LOW

### E1-L-1 — `GET /webhooks/events` has no scope preHandler (inconsistent with every sibling route)

**File:** `backend/src/routes/webhooks.ts:52` — `authed.get('/webhooks/events', async () => ({ events: WEBHOOK_EVENT_CATALOG }))` with no `preHandler`, inside a block where every other route carries `requireScope('webhooks:read'|'webhooks:write')` or `requireRoleOrScope`.

**What's wrong:** only that it's inconsistent: any authenticated session (any role, including `viewer`) and any API key regardless of scopes can read it. Impact is negligible — it returns a static event-name catalog, no tenant data — but the B1-M1 pattern ("every route gets a scope gate") is broken here, and the next person to add a field to that response won't notice the missing gate.

**Fix:** add `preHandler: requireScope('webhooks:read')`.

**Duplicate check:** no prior pass mentions this route. **NEW.**

### E1-L-2 — Invitation throttle shares the spend bucket; 30 invite-emails/hr is a bounded outbound-spam vector

**Files:** `backend/src/routes/account.ts:382` (`expensiveTenantLimit()` on `POST /account/invitations`), `backend/src/middleware/rateLimit.ts:14`, `backend/src/config.ts:40` (default 30/hr).

**What's wrong:** the D1-L-12 throttle exists (good), but it reuses the *same* 30/hr/tenant `expensiveTenantLimit()` bucket as keyword research, content/geo generation, and rank spend. Two consequences: (a) coupling — a tenant doing heavy legitimate spend work can starve its own invite flow and vice versa; (b) abuse — a compromised `editor` account (editors may invite, account.ts:382) can emit 30 invitation emails/hour to arbitrary addresses from the platform's sender identity, indefinitely. Bounded, logged (`invite.sent` activity), and each invite is single-use/email-bound — hence LOW, not MEDIUM.

**Fix:** give invitations their own named bucket (e.g. `inviteLimit()`, 10–20/hr) separate from the spend budget; optionally require owner/admin (not editor) to invite, or add a per-target-email cooldown.

**Duplicate check:** D1-L-12 added the throttle; no prior pass critiques the shared bucket or the editor-may-invite spam angle. **NEW.**

## Verified clean (focus areas with no finding)

**Trial gate (focus #2):**
- `requireActiveSubscriptionOrTrial` is wired on **every** spend route in all 8 listed files (keywords 4 routes, ranks 1, content 7, geo 2, audit 1, reports 8, competitors 2, backlinks 3) — each verified individually against its handler body (DataForSEO/LLM enqueue confirmed). Ordering is correct everywhere: `requireVerifiedEmail` → trial gate → `expensiveTenantLimit()` → role/scope, so unverified users 403 before any `read_only` flip.
- `subscriptions.tenant_id` is `UNIQUE` (migrations/001_init.sql:151) — the gate's `LEFT JOIN … rows[0]` cannot hit multi-row ambiguity.
- Expired-trial → `read_only=TRUE` + `402 SUBSCRIPTION_REQUIRED`; subscribing later resets `read_only=FALSE` (`providers/stripe.ts:562`), so paying users recover.
- `/billing/checkout` and `/billing/portal` are deliberately ungated (the subscribe path); mock-confirm is mock-only and tenant-scoped (`billing.ts:421-444`).
- Non-spend mutations (track/untrack, approve, brief, tracking-config PATCH, CSV upload, prompt CRUD) correctly carry no gate — DB-only, no provider cost.

**GSC disconnect (new, D1-L-10):** `POST /sites/:id/gsc/disconnect` (`gsc.ts:106-119`) — `requireRoleOrScope(['owner','admin','editor'], 'sites:write')`, `requireSite()` tenant scoping, UUID param schema, clears `gsc_refresh_token_enc`. Clean. (GA4 mirror at `ga4.ts:144` likewise.)

**apikeys role change (D1-L-11):** `GET /apikeys` is now `requireHumanSession` + `requireRole('owner','admin')` (was broader) — verified in place. POST/DELETE additionally human-only; the `'admin'` scope is unmintable into keys (`apikeys.ts:80-88`), so a stolen key can never mint/persist keys. Clean.

**Invitation throttle (D1-L-12):** `expensiveTenantLimit()` present on `POST /account/invitations`; `inviteSchema` enums roles, `canAssignRole` blocks self-or-above grants (editor can only invite viewers); NEW-2 indistinguishability holds — the INSERT + identical `202` shape happen for both new and cross-tenant emails, and `token_hash` is never listed (`account.ts:453`). Clean apart from L-2 above.

**AuthZ / IDOR / tenant isolation (focus #1):** `requireSite(tenantId, id)` + `tenant_id = $1` scoping held on every sampled mutation (sites, keywords, ranks, content, geo, audit, backlinks, competitors, reports, onpage, workspaces, alert-rules/digest per-user scoping). `requireRoleOrScope` semantics verified in `access.ts` (sessions by role-rank, keys by scope, `'admin'` scope implies all but is unmintable). Platform admin behind a global `requirePlatformAdmin` hook returning 404 (`admin.ts:78`). Share-token public endpoints HMAC + tenant-bound (as pass4 verified). No bypass found.

Dynamic SQL (`content.ts` PATCH, `ranks.ts` tracking PATCH, backlink CSV batch INSERT) is fully parameterized. All server-side fetches of user-controlled URLs go through `safeFetch` (onpage, domain verification, webhook delivery, notifications). No new injection vector found.

**Read-only machinery:** `enforceTenantState` blocks POST/PUT/PATCH/DELETE for read-only tenants while exempting `billing|admin|account|apikeys|settings|auth|webhooks` so expired users can still subscribe/manage — sound, except for the GET-with-spend hole folded into H-1.
